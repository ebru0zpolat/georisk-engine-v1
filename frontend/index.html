Platform Architecture

Four stages.
One auditable workflow.

What this repository ships today: labelled connectors with fallbacks, a five-layer portfolio path, deterministic scoring, and REST delivery — no GraphQL, no invented throughput SLAs, no black-box AI claims.

01 / CONNECTORS

ORAS5 + Earth Engine

Production connectors pull ORAS5 ocean reanalysis (CDS Zarr) and GEE proxies (VIIRS night lights, Sentinel-5P NO₂). When credentials are unset, deterministic fallback features keep local/CI runs coherent and labelled.

GET /v1/data-sources
02 / FIVE-LAYER PATH

Hazard → financial translation

Portfolio workflow: hazard × exposure × vulnerability → Phase A scenario-loss proxy (under an “EAL” label) → adaptation and avoided-loss evidence. Current damage curves are synthetically calibrated and labelled as such.

Methodology v0.3.1 · Phase A proxy
03 / LINEAGE

Versioned evidence

Methodology and pack versions, parameters, and a hash-chained append-only financial audit trail. Independent recomputation proves reproducibility of selected EAL numbers — not empirical loss accuracy.

audit trail · verify-eal CI
04 / DELIVERY

REST API + demo

Point score, portfolio ingest, scenario runs, Markdown/PDF reports, and OpenAPI via FastAPI /docs. No GraphQL surface and no webhook product in this repository.

Claim control

Nine states.
Every number carries one.

A measurement, a connector fallback and a synthetically calibrated parameter are not the same claim, so they never look the same. The chip sits beside the value, one per value, and its wording is the same string used in the audit trail and in exports.

✓VERIFIED authoritative source, version pinned
⟲LIVE fetched from the connector in this run
▤FIXTURE pinned sample or fallback, not a measurement
≈MODELLED methodology output, version stated
ƒDERIVED arithmetic on values shown here
⚗SYNTHETIC synthetically calibrated, labelled as such
◐DEGRADED a connector was partly unreachable
◷STALE past its freshness policy
⊘NOT_ELIGIBLE gates fail closed — decision-support only

Request & response contract

Required for POST /v1/risk/score:

  • asset_name (string)
  • latitude (−90…90, decimal degrees WGS84)
  • longitude (−180…180, decimal degrees WGS84)

Common optional fields:

  • radius_km (default 10; >0 and ≤100)
  • preset_id (registered presets; default industrial_v1)
  • sector (reporting label; default industrial)
  • include_industrial_verification_ref (bool; default false on score)

Main response fields: overall_score (0–100), risk_band, risk_score ([0,1]), components, flags, audit_id, meta.data_version, optional industrial_verification.

Validation: unknown preset_id, out-of-range coordinates, or missing required fields → HTTP 422 with the standard error envelope.

Errors & operational limits

Standard envelope:

{ "error": { "code": "VALIDATION_ERROR", "message": "Field required", "details": {} } }
  • 422 — schema / coordinate / preset errors (VALIDATION_ERROR, INVALID_COORDINATES, PRESET_NOT_FOUND, …)
  • 413 — POST /v1/portfolio/upload body above default 2 MB (PORTFOLIO_UPLOAD_MAX_BYTES)
  • 429 — mutating methods exceed default 60 requests / 60s per client IP (RATE_LIMIT_EXCEEDED); X-RateLimit-* headers on responses
  • 404 — unknown async batch task_id (NOT_FOUND)

Health and OpenAPI docs paths are exempt from the mutating-method rate limit. Branch on error.code, not message text.
